This section records my personal feedback after participating in the **First Cloud AI Journey (FCAJ)** internship program. I write this part from the point of view of a student who learned a lot, struggled with several technical gaps and gradually became more comfortable working with AWS through labs, events, documentation and team project work.

## Overall Reflection

FCAJ gave me a practical environment that is very different from normal coursework. In school, many assignments are limited to a clear requirement and a fixed grading rubric. In this program, I had to deal with topics that are closer to real cloud work: choosing services, understanding IAM permissions, thinking about cost, checking security, preparing documentation and explaining the reason behind each technical decision.

What I appreciated most was that the program did not only introduce AWS services as theory. The weekly worklog, technical blogs, events and workshop project forced me to connect ideas together. IAM was no longer just a permission topic. It appeared again in ECS task roles, Lambda permissions, S3 access and CI/CD automation. CloudWatch was not only a monitoring service. It became part of reliability, demo preparation and cost awareness.

## Program Strengths

### 1. Practical Learning Direction

The program encouraged hands-on learning instead of passive listening. Each topic had to be connected with labs, references or project work. This helped me remember AWS services through actual use cases rather than memorizing definitions only.

### 2. Strong Community Atmosphere

The events and community activities made the internship feel more alive. Listening to speakers and seeing other student teams work on AWS topics helped me understand that cloud learning is not a single-person journey. It requires asking questions, comparing approaches and learning from people who are ahead.

### 3. Exposure to Real Engineering Mindsets

The program helped me learn several mindsets that are important beyond a single project:

- security should be considered early, not only at the end,
- cost must be checked continuously, especially in student AWS accounts,
- monitoring should focus on user experience, not only infrastructure health,
- documentation is part of engineering work, not an afterthought.

### 4. Room for Personal Growth

FCAJ pushed me to work on weaknesses that I could avoid in smaller school projects. I had to organize notes, write bilingual content, handle Git changes, check references and make the report consistent. These tasks were not always exciting, but they were necessary and taught me discipline.

## Personal Challenges

The most difficult part for me was connecting many concepts at the same time. A single deployment flow can involve Docker, ECR, IAM, ECS Fargate, security groups, ALB, CloudWatch and cost cleanup. At first, I sometimes understood each service separately but did not immediately see the full path.

Another challenge was writing in a way that sounded like my own work. Technical reports can easily become too formal, too generic or too similar to a template. Through the revision process, I learned to write more honestly: what I studied, what I understood, what I still need to improve and how each reference supports the report.

## Feedback for Future Cohorts

### What Worked Well

- The weekly learning structure gave students a clear direction.
- Community workshops and events helped connect AWS theory with real stories.
- The final project format gave students a reason to combine cloud, DevOps, security and documentation.
- Having both English and Vietnamese content helped improve technical communication.

### Suggestions for Improvement

- Add short weekly office-hour sessions so teams can ask technical questions before problems accumulate.
- Provide a sample low-cost AWS account checklist at the beginning, including Budgets, cleanup reminders and common paid services to watch.
- Give students a simple reference architecture template for the first project draft, then allow each team to customize it.
- Add a short Git workflow session covering branch strategy, rebase, conflict resolution and safe pull/push habits.
- Include more presentation practice before the final demo so students can explain architecture decisions more confidently.

## What I Would Tell New Students

If a new student asks me whether FCAJ is worth joining, my answer is yes, but they should join with the right expectation. FCAJ is not a program where everything is handed to you step by step. It gives direction, community and opportunities, but each student still has to read, try, fail, fix and document their own learning.

The students who gain the most from FCAJ will probably be the ones who are willing to ask questions, keep notes, clean up after labs and review why a configuration works instead of only copying commands.

## Closing Note

I am grateful to the AWS team, mentors, speakers and friends in the FCAJ community for creating a learning environment where students can experience cloud engineering more realistically. This internship helped me become more serious about how I learn technical topics and how I present the result of that learning.

The program also reminded me that becoming better at cloud engineering is a long process. This report is not the end of that process. It is a milestone that shows what I have learned so far and what I need to continue improving after the internship.
